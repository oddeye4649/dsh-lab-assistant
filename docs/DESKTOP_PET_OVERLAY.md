# 桌面桌宠与外部软件操控方案

## 结论先说

1. 现在的插件**只能画在 DSH 页面里**，不能跑到桌面、不能框住 eNSP 窗口、不能替你点 eNSP。
2. 要做到“桌宠在任意窗口上方移动并指按钮”，必须增加一个**独立的桌面伴随进程**（overlay），插件通过本机 IPC 指挥它。
3. 操控 eNSP 做实验，**管理员权限不是主要门槛**。真正的门槛是 UI 自动化、设备启动等待、控制台输入和截图可信度。

## 为什么插件本身出不去

DSH 插件运行在 DSH 的渲染进程里，能操作的只有当前网页 DOM：

- 不能创建跨应用的置顶透明窗口；
- 不能读取其他进程窗口的位置和控件树；
- 不能向其他窗口发送键盘鼠标；
- 不能截取被遮挡的外部窗口。

所以“页面内高亮”和“桌面级指引”是两种不同的运行形态，不是加几行 CSS 能解决的。

## 目标形态

```text
DSH 插件（实验档案 / 步骤 / 报告）
        │  本机 HTTP + token（127.0.0.1）
        ▼
桌面伴随进程（overlay）
  ├─ 透明置顶窗口：桌宠、气泡、箭头
  ├─ 高亮层：按屏幕坐标画框，可点击穿透
  ├─ 窗口感知：前台窗口、标题、进程名、控件矩形
  └─ 截图：PrintWindow / BitBlt
        │
        ▼
目标软件（eNSP、Wireshark、浏览器…）
```

## 技术选型

| 方案 | 体积 | 能力 | 代价 |
|---|---|---|---|
| WPF / .NET Framework 4.8 | 10–20 MB | Win32、UIA、透明置顶、点击穿透都成熟 | 仅 Windows；界面用 XAML |
| Tauri v2 + WebView2 | 5–15 MB | 可复用现有 HTML/CSS 桌宠 | 需要 Rust 工具链构建；WebView2 依赖 |
| Electron | 150 MB+ | 前端复用最好 | 体积大；与 DSH 自带 Electron 不应混用 |
| 原生 Win32 C++ | <5 MB | 最轻、最可控 | 开发慢，UI 成本高 |

MVP 建议 **WPF**：Windows 10/11 自带 .NET Framework 4.8，不需要用户额外装运行时；Win32 互操作直接。

## 关键窗口技术

- 透明置顶：`WS_EX_LAYERED | WS_EX_TOPMOST | WS_EX_TOOLWINDOW`，不占任务栏。
- 点击穿透：`WS_EX_TRANSPARENT`，或 `WM_NCHITTEST` 返回 `HTTRANSPARENT`；需要交互时临时关闭穿透。
- 高 DPI：manifest 声明 `PerMonitorV2`，按 `GetDpiForWindow` 换算，否则 150% 缩放下框会偏。
- 多显示器：用物理像素坐标，不要用 WPF 的逻辑单位直接换算。
- 高亮外框：`GetForegroundWindow` + `DwmGetWindowAttribute(DWMWA_EXTENDED_FRAME_BOUNDS)` 拿真实边界；控件级用 UI Automation 的 `BoundingRectangle`。
- 截图：`PrintWindow(hwnd, hdc, PW_RENDERFULLCONTENT)` 可截被遮挡窗口；GPU 渲染/DRM 窗口可能黑屏，需要回退到桌面 `BitBlt`。

## 指引怎么落地

```text
实验步骤（来自档案）
→ 找到目标窗口：进程名 + 标题正则
→ 找控件：UIA 控件树（名称/类型/AutomationId）
→ 找不到：回退到“模板截图 + 相对坐标”，并标注“按当前分辨率录制”
→ overlay 画框 + 桌宠移动到旁边 + 气泡说明
→ 用户操作
→ 校验：前台窗口/控件状态/日志/截图
→ 通过则进入下一步
```

### 控件定位的可靠性分级

| 级别 | 方式 | 稳定性 |
|---|---|---|
| A | UIA 的 AutomationId / Name | 版本小幅变化仍可用 |
| B | 控件类型 + 层级路径 | 版本升级可能失效 |
| C | 模板截图匹配 | 换主题/分辨率就失效 |
| D | 固定屏幕坐标 | 只在录制环境有效 |

eNSP 是 Qt 应用，UIA 暴露程度有限；多数控件需要 B/C 级方案，升级后要重新录制。

## eNSP 能不能自动做实验

分三层看：

### 1. 打开软件、搭拓扑

- 可以用 UIA/坐标自动化拖设备、连线；
- 但设备图标位置随版本与窗口大小变化，需要每个版本一套页面地图；
- 拓扑文件（.topo）可以直接生成并由 eNSP 打开，这比模拟拖拽可靠得多。

### 2. 启动设备并配置

- 设备实际运行在 VirtualBox 虚拟机里，启动需要几十秒，必须轮询状态；
- 配置通常在设备 CLI 控制台里输入命令，属于串口/终端交互；
- 这部分可以用“生成配置脚本 + 用户粘贴”半自动完成，比模拟键盘可靠。

### 3. 验证与截图

- ping/tracert 结果要真实执行后截图，不能合成；
- 需要确认设备真的启动，否则截图只是空壳。

因此现实路线是：

```text
自动：生成拓扑、生成配置命令、打开目标窗口、定位按钮、截取结果
人工：确认设备启动、粘贴命令、确认结果
```

**不建议承诺“全自动替学生做实验”**，既不可靠，也违背实验报告的真实性要求。

## 管理员权限到底什么时候需要

| 操作 | 是否需要管理员 |
|---|---|
| 截屏、置顶窗口、UIA 读取 | 否 |
| 向普通权限程序发送键鼠 | 否（同完整性级别） |
| 向以管理员运行的程序发送键鼠 | 是（UIPI 拦截） |
| 安装 WinPcap/Npcap 驱动 | 是 |
| 创建/修改 VirtualBox Host-Only 网卡 | 通常是 |
| 改 Hyper-V/VBS、注册表、服务 | 是 |
| 读取其他用户进程内存 | 是 |

所以“能不能自动做实验”与管理员权限关系不大；**卡点是控件识别、版本差异和设备启动状态**。  
本插件不内置提权通道：普通截屏、录结果、生成报告都不需要管理员；确实需要驱动级操作时，由使用者自行以管理员运行 DSH。

## 分阶段计划

### P0 桌面桌宠 + 外部高亮（可先做）

- 独立 overlay 进程，置顶透明、点击穿透开关；
- 接收插件指令：显示气泡、移动到屏幕坐标、框选窗口/控件；
- 截取前台窗口，存进实验档案 `screenshots/`；
- 手动“下一步”，不做自动点击。

### P1 窗口感知与自动推进

- 监听前台窗口切换，匹配步骤里配置的窗口/标题；
- 用户切到目标窗口就自动推进并提示下一步；
- 失败时提示“当前窗口不是目标窗口”。

### P2 常用软件页面地图

- 为 eNSP、Wireshark、MySQL Workbench 等录制控件树与截图；
- 按版本存页面地图，升级后重新采集；
- 高亮改用 UIA 矩形，坐标只作回退。

### P3 eNSP 半自动实验

- 生成 .topo 拓扑文件 + 配置命令清单；
- 引导用户打开拓扑、启动设备、粘贴命令；
- 自动收集 ping/路由表输出截图，写入报告；
- 不自动点击“启动设备”以外的危险操作。

## 已确认的决定（2026-10-28）

1. **Windows-only**：首版用 WPF / WinForms + .NET Framework 4.8（系统自带），不做 macOS/Linux。
2. **桌宠是展示，但可点开设置**：桌宠本体可点击，打开小设置页（称呼、是否隐藏桌宠）；其余区域点击穿透，不挡用户操作。
3. **随 DSH 启动**：DSH 插件启动时拉起伴随进程，退出时释放；不单独注册开机自启，不常驻后台。

对应实现要求：overlay 用命中测试把“桌宠区域”置为可点击，其他区域 `HTTRANSPARENT`；设置页与桌宠同一个进程，不从 DSH 页里弹窗。

## P0 实现状态（0.5.0）

已落地：

- `overlay/LabPet.cs` + `app.manifest`：WinForms 伴随进程，含透明置顶桌宠（拖动、点击开设置：称呼/大小/隐藏/退出）、全屏点击穿透高亮层、不抢焦点气泡、UIA 窗口/控件定位、PrintWindow 截图、本机 HTTP 控制（127.0.0.1 + token）。
- `lib/overlay.mjs`：首次运行编译到 `$DSH_HOME/lab-assistant/overlay/`，随 DSH 启动、插件卸载即退出。编译走两条路：装了 Visual Studio 用它的 Roslyn，没装退回系统自带的 .NET Framework 编译器（C# 5）；`DSH_LAB_FORCE_FRAMEWORK_CSC=1` 可强制走后者（排错/复现用户环境用）。失败会降级并在 `lab_desktop_status` 里说明原因。
- 插件工具：`lab_desktop_status / pet / guide / screenshot`、`lab_page_map_capture / guide / list`。

边界（如实）：

- 定位靠 UIA 控件名 + 窗口标题/进程名；Qt 类程序（如 eNSP）控件暴露有限，找不到控件时回退为高亮整个窗口。
- 不代替用户点击；只读定位 + 截图。
- 截图依赖 PrintWindow，GPU/DRM 窗口可能黑屏，届时换前台截图（后续增强）。
- 编译/运行链路已在真机验证两条编译器路径（0.15.18 P4a：旧编译器 991 ms、Roslyn 1379 ms，均能启动）；仍未覆盖杀软拦截、缺 .NET Framework、只读目录首次编译，失败时 `lab_desktop_status` 会给出原因和 `build.log` 路径。

## 0.6.0：实验助手面板上桌 + 网页桌宠下线

- 点桌面桌宠弹出**实验助手面板**（WinForms）：实验档案列表/打开实验目录、新建实验、生成报告（姓名/学号/模板可直接浏览）、桌宠设置（称呼/大小/显示）。
- 数据来源：插件启动时开一个仅本机、带随机 token 的 IPC 端口（复用 `/dsh-lab/api/*`），把地址通过 `--api/--apitoken` 传给伴随进程；DSH 卸载插件时一并关闭。
- DSH 网页不再注入 pet.js/css 与任何 UI；`/dsh-lab/pet.js` 返回 404。
- 全屏永远只有一只大肥鱼。

## 与现有插件的关系

- 插件仍是“大脑”：实验档案、步骤、版本诊断、报告生成。
- overlay 只是“眼睛和手指”：显示、定位、截图、可选点击。
- 两者用本机 token 鉴权，只监听 `127.0.0.1`，不开放公网。

## 桌宠动作与状态机（0.7.x）

- 状态集合：`idle`（待机）、`swim`（走动）、`point`（指向）、`happy`（开心）、`confused`（疑惑），外加 10 种待机小动作（`drink`/`typing`/`read`/`stretch`/`wave`/`sleep`/`snack`/`music`/`wipe`/`spin`）。
- 触发来源：
  - 插件 API：`POST /pet {"action":"state","state":"happy","durationMs":4000}`。
  - `lab_desktop_guide` 定位成功时自动切到 `point`，并保持高亮时长。
  - 新建实验、报告生成成功 → `happy`；报告生成失败 → `confused`（由插件在本地调用，不经过模型）。
  - 空闲且开启“桌面自由走动”时，桌宠在工作区内随机走到目标点，期间显示 `swim`；到达后停 3~6 秒。
  - 拖动桌宠、打开“实验助手”面板时暂停自动走动。
  - 待机小动作在空闲时随机触发，每轮持续约 5 秒，两轮之间间隔 20~60 秒；由「待机动画与说话」开关控制。
- 引导冲刺：`PositionNear` 不再瞬移，改为固定 8 帧（约 0.5 秒）滑行到位，距离再远也不会拖沓；到达后立刻恢复 `point` 表情。
- 左右朝向：素材只需朝右；`facingLeft` 由移动方向决定，绘制时用 `ScaleTransform(-1,1)` 水平镜像。
- 走动动效：垂直小跳（`|sin|*4px`）+ 倾斜摆动（±1.6°），避免纯平移。
- 动效兜底：无动画帧时用程序内变换（呼吸缩放、上下轻浮、走动小跳）；有 `<name>_1..N.png` 时按约 240ms 一帧循环，单张 `<name>.png` 也兼容。
- 图片自动发现：启动时扫描 `assets/pet/*.png`，按 `_数字` 后缀分组，新增动作无需改代码。
- 闲聊：本地预设台词，随机 40~90 秒一次气泡，可在面板关闭；**不消耗模型 token**。
- 配置字段：`chatter`（默认 true，控制待机小动作与说话）、`wander`（默认 true），存在 `config.json`。

## 0.14.3：本机接口收紧（安全与稳定性）

- **校验命令白名单**：`/tutorial` 的 `verifyCmd` 先过 `VerifyCommandAllowed`（mysql / python / node / java / git / dir / echo …），并拒绝 `&`、`|`、`<`、`>`、`^` 与控制字符。
  白名单只认第一个 token，不堵串联等于没堵；引号内的内容不参与符号检查（`mysql -e "select 'a&b'"` 仍然放行）。
- **截图落点受限**：`/screenshot` 的 `out` 只允许 `<实验>/screenshots/<文件>`、临时目录或配置目录内的路径，其余直接拒绝，
  避免把任意可写文件覆盖成 PNG。最小化窗口先 `EnsureRestored` 再取尺寸。
- **不再交出白图**：`PrintWindow` 返回 false 时退回 `CopyFromScreen`；恢复窗口后重新量 rect，避免截到错位画面。
- **不阻塞消息循环**：stdout/stderr 双管道异步读，15 秒超时后 `taskkill /PID … /T /F` 结束整棵进程树，再兜底 `Kill()`。
- **本机监听**：`ReceiveTimeout` / `SendTimeout` = 10 秒，请求体上限 2 MB。
- **坐标统一**：`/guide` 的 `client` 默认改为 `false`（整窗），与 `/screenshot`、`/click` 同一基准；旧版客户区基准的位置经验会被忽略并重新积累。
- **配置原子写**：`config.json` 先写 `.tmp` 再 `File.Replace`，避免多进程并发写出半截 JSON。
- **口令不进对话、不落盘**：`/tutorial` 新增 `env` 字段，`MYSQL_PWD` 这类口令只存在伴随进程内存里，执行校验命令时才写进子进程环境；
  插件侧会把启动 DSH 时已设的同名环境变量自动透传，不必把口令打进聊天。

> 边界说明：这套白名单降低的是**误用与误触发**的面，不是沙箱。`python -c`、`node -e`、`java -jar` 本身就能执行任意代码，
> 同用户进程本来也有权限自己起 `cmd.exe`。真正的边界是「只监听 127.0.0.1 + token + 不联网」。
