# 实验报告引擎

## 目标

把“按老师模板写报告”里最耗时的部分自动化：**读懂模板结构 → 对上实验档案 → 生成可编辑的 Word 初稿**。  
不代替你写实验结论，也不编造任何未发生的实验数据。

## 流程

```text
导入模板 (.docx / .md / .txt)
→ 解析：标题层级、章节、表格列、封面字段、模板提示语
→ 读取实验档案：步骤、截图、数据文件、备注、故障记录
→ 逐节判定 coverage
→ 生成 Word(.docx) + Markdown
→ 输出“还要补”清单与【待补】计数
```

## 模板解析规则

### 章节

- `.docx`：读 `word/document.xml`，按 `Heading 1..6` / `标题 N` / `outlineLvl` 判断层级。
- `.md`：按 `#` 数量判断层级。
- 第一个一级标题如果像文档标题（含“报告/模板/实验名称”，或后面还有更深层级标题），会被当成报告标题，不计入章节。
- 每个标题按关键词归入类型：

| 类型 | 触发词 | 自动填充 |
|---|---|---|
| purpose | 目的、目标、要求 | 自动草稿（用步骤与预期组织） |
| principle | 原理、理论、背景 | 自动草稿（软件信息 + 操作对象） |
| environment | 环境、器材、设备、工具 | 是（只读探测） |
| topology | 拓扑、组网、结构图 | 有文件名含“拓扑”的截图时自动插入 |
| steps | 步骤、过程、内容、方法 | 是（档案步骤） |
| results | 结果、数据、记录、现象 | 是（截图/数据/备注） |
| analysis | 分析、讨论、思考 | 自动草稿（有真实证据时） |
| problems | 问题、故障、排错、异常 | 是（本机经验库） |
| summary | 总结、心得、体会、结论 | 自动草稿（用步骤与排错记录） |
| references | 参考、文献、资料 | 否 |

“结果分析”会优先归为 analysis，不会被当成 results。

### 表格

- 章节下第一张表的第一行作为表头，生成时保留同样的列。
- 结果表的“测试项/预期”按步骤预填；“实际结果”只取 `lab_experiment_record_result` 记录的真实实测值，没有记录则留【待补】；“结论/判定”只在明确记录了通过/未通过时填“符合预期/不符合预期”。
- 封面表格（第一个标题之前的表）按第一列识别为字段名，例如：实验名称、姓名、学号、班级、指导教师。

### 封面字段映射

| 字段 | 来源 |
|---|---|
| 实验名称 / 题目 | 实验档案标题 |
| 课程 / 科目 | 实验档案课程 |
| 软件 / 平台 | 实验档案软件 |
| 姓名 | 生成时传入 |
| 学号 | 生成时传入 |
| 班级 / 专业 / 学院 | 留空【待补】 |
| 指导教师 | 留空【待补】 |
| 日期 | 生成当天 |
| 编号 | 实验编号 |

## coverage 语义

- `auto`：内容全部来自真实档案或只读探测。
- `draft`：根据真实步骤/软件信息/数据摘录组织的文字草稿，必须本人核对。
- `partial`：有框架但缺关键内容（例如没有故障记录）。
- `pending`：必须人工写，生成时标【待补】。

覆盖度 = `(auto + draft × 0.75 + partial × 0.5) / 总章节`，只是进度参考，不是质量评分。

四类文字章节的草稿来源：

| 章节 | 依据 |
|---|---|
| 目的 | 实验标题、课程、软件、步骤与预期 |
| 原理 | 软件目录中的类别与说明、步骤涉及的操作对象 |
| 分析 | 步骤数、截图数、数据文件数、数据文件前几行真实摘录 |
| 总结 | 步骤清单、本机经验库里的排错记录 |

草稿直接写入报告正文，**不会出现“自动草稿/需核对”这类字样**，也不会写“已验证成功”这种结论；核对清单只在面板和 plan 里展示，不进报告。

## 输出

- `reports/<实验名>-<日期>.docx`：标题样式、表格、内嵌截图（最多 6 张，宽 5.8 英寸等比缩放）。
- `reports/<实验名>-<日期>.md`：同样的内容，方便版本管理和二次编辑。
- 报告本体不含生成器痕迹；缺少的数据格子标【待补】，其余就是可直接编辑的内容。

## 已知限制

- 只还原结构，不还原学校模板的字体、页眉页脚、分节、自动编号、公式、图表题注样式。
- 扫描版 PDF、图片式模板不支持；请提供 .docx 或可复制的 Markdown。
- 表格合并单元格会被展平，复杂表头需要手工调。
- 不读取旧报告内容来“模仿文风”，避免把别人的数据带进来。
- 文字稿是模板化组织，不理解实验内容的深层含义；原理与分析仍需按教材改写。
- 报告里不出现任何“自动草稿/模板要求/生成器”字样；实测值必须来自真实记录，模型不猜测。
- 图片最多 6 张、单张 8 MB，超出会跳过并在 coverage 里体现。

## 隐私与安全

- 模板只在本机解析，解析结果存 `$DSH_HOME/lab-assistant/report-templates/`。
- 报告写入实验档案的 `reports/` 目录，不上传。
- 不执行模板里的宏；.docx 只读 `document.xml` 文本与结构。

## 代码与测试

- `lib/zip.mjs`：最小 zip 读写（无第三方依赖）。
- `lib/docx-read.mjs`：docx/markdown → 结构化 blocks。
- `lib/docx-write.mjs`：报告模型 → docx（含样式、表格、图片）。
- `lib/report.mjs`：模板画像、填充计划、生成。
- `test/report.test.mjs`：10 条测试，覆盖 zip 往返、docx 往返、模板识别、封面字段、占位符、错误输入。
- 生成的 docx 额外用 `python-docx` 打开验证：标题样式、表格数量、内嵌图片数量均可读。
